### 刻意不做的（设计决策，非遗漏）

协议里的「重复次数（rp）」「优先级（pr）」在某一轮被移除，理由写在 `internal/config/config.go:412`：
> 宏本身按轮循环触发，玩家无需理解它们。

D3keyHelper 的界面同样**没有**暴露这两项，行为一致。

## 三、界面重构交接

### 逻辑与界面是分离的

**重构界面只需改这两个文件**：

| 文件 | 内容 |
| --- | --- |
| `window.go` | 主窗口（三段式布局）、槽位表、设置对话框、助手面板 |
| `logwindow.go` | 日志窗口 |

`main.go` 里有少量界面相关代码（托盘菜单、对话框调用），可按需调整。

### 界面依赖的接口（重构时保持不变即可）

- `app.settings`（`*store.Settings`）—— 工具级设置，含智能暂停 / 助手 / 悬浮窗
- `app.st.snapshot()`（`runtimeSnapshot`）—— 运行期快照：引擎、协议配置、目标进程、启动模式、各种运行时开关
- `internal/games` —— 游戏适配器（`All()` / `For(id)` / `DefaultAdapter()`），提供槽位定义与暗黑3 的坐标、界面识别
- `internal/helper` —— `All()` 返回全部助手的 `ID()` 与 `Name()`，界面按它动态生成开关
- `internal/store` —— `LoadSettings` / `SaveSettings` / `Snapshot` 等
- `internal/engine` —— 引擎只需 `SetEnabled` / `Toggle` / `Paused` / `SetProfile` 等控制方法

### 所有控件引用集中在 `mainWindow` 结构体

`window.go` 顶部的 `mainWindow` 结构体列出了全部控件指针（`gameCombo`、`tabWidget`、`slotKeyBtns` 等）。
重构时按新布局增减字段即可，逻辑层不感知。

### 当前布局结构

```
主窗口 (VBox)
├── 全局控制 (GroupBox，横跨整宽)
│     第一行：当前游戏 / 宏状态 / 启动快捷键 / 启动方式
│     第二行：左键自动站立 + 键位 / 窗口化提示 / 保存·导入·导出·更多设置·日志
├── 主体 (TabWidget，4 个方案页)
│     每页：按键宏设置（6 列槽位表）+ 本配置设置
├── 助手功能（暗黑3）(GroupBox)
│     第一行：助手快捷键 / 动画速度 / 重铸目标 / 开发者模式
│     第二行：各助手开关（按 helper.All() 动态生成）
│     第三行：窗口化与宏互斥提示
└── 底部状态栏：当前激活配置 / 目标进程 / 技术路线
```

### 已知的界面技术限制（重构时会遇到）

1. **walk 是 Win32 原生控件的封装**，控件的画法（按钮圆角、下拉直角、字体渲染）由系统决定，代码改不了。要统一风格必须**自绘**（walk 的 `CustomWidget` / OwnerDraw + GDI）或换渲染层（如 WebView2）。
2. **窗口尺寸由内容撑开**：`fixedWinWidth` / `fixedWinHeight` 是设定值，但控件总宽超过它时窗口会变大。当前实际客户区约 1262×862。
3. **控件高度必须统一**（已有常量 `ctrlHeight = 26`）：高度不一致时 walk 会让各控件在行内各自居中，视觉上就是"有的偏上有的偏下"。
